# Forge R2-06 — интеграционная регрессия и архитектурный допуск

**Решение: GO WITH DOCUMENTED DEBT.** На `8c9ae2b67bcbbe89a939b782e2e62191acc2efac` проверки поддерживают переход к проектированию Week 4 Step 10, Independent Verification v1, в пределах доверенного fixture workspace. Verification должен независимо наблюдать фактический результат, связывать evidence с конкретными run и workspace и допускать `succeeded` только при подтверждении критериев. Частичный или неизвестный файловый эффект требует отдельного вывода проверки. Автоматический повтор write и durable resume остаются отдельными задачами.

## Межкомпонентные сбои

- **Отмена между commit proposal и publish.** Тесты R1A останавливают реальный close после commit. Независимая сессия сначала видит `proposed/pending`, затем сверка закрывает заявку по сохранённым метаданным без запуска handler. Вариант ошибки cleanup сохраняет исходную причину и освобождает slot. Возможен незавершённый durable proposal для отдельной диагностики. [Тесты R1A](../backend/tests/test_proposal_interruption_integration.py#L155)
- **Reject одновременно с global deadline.** При уже закоммиченном reject и подавленной доставке уведомления остаются `failed/denied/rejected`. Внешняя причина и agent failure event — `execution_deadline_exceeded`, audit ToolCall сохраняет `approval_rejected`. [Тест гонки](../backend/tests/test_approved_repository_integration.py#L579)
- **Отмена после claim до handler.** `tests/test_approval_integration.py::test_postgres_cancellation_after_claim_commit_never_invokes_handler` наблюдает committed допуск и подтверждает отсутствие вызова handler при доставленной отмене. [Тест после claim](../backend/tests/test_approval_integration.py#L478)
- **Сбой audit после изменения файла.** В `tests/test_approved_repository_integration.py::test_postgres_approved_graph_persistence_failure_never_fabricates_success[final-audit]` файл изменён, а независимый read видит `AgentRun.failed`, `ToolCall.running` и `Approval.approved`. В `test_postgres_approved_graph_cancel_after_mutation_keeps_observed_file_change` мутация также переживает отмену. PostgreSQL и файловая система имеют отдельные границы commit. [Сбой аудита](../backend/tests/test_approved_repository_integration.py#L754) · [Отмена после мутации](../backend/tests/test_approved_repository_integration.py#L843)
- **Поздний callback.** После закрытия holder отклоняет позднюю публикацию. Если результат runner приходит после terminal cancellation, `complete_execution` требует `running`; тест позднего результата фиксирует отсутствие перезаписи. Повтор durable evidence может подтвердить уже завершённую операцию с одним failure event, конфликт или чужой reference оставляет stale-state guard. [Holder tests](../backend/tests/test_approval_outcome.py#L26) · [Поздний результат](../backend/tests/test_agent_service_integration.py#L388) · [Outcome PG](../backend/tests/test_approved_repository_integration.py#L242)
- **Task/Workspace rollback.** После конфликтующего Task insert отдельное соединение видит прежнюю строку. При rollback выигрывающего insert ожидающий writer получает ключ. Workspace проверен по обе стороны подтверждённого commit. При потере подтверждения отсутствие строки требует отдельного чтения. [Task rollback](../backend/tests/test_task_idempotency_integration.py#L339) · [Workspace](../backend/tests/test_service_transactions.py#L109)
- **Restart.** `tests/test_approval_integration.py::test_postgres_restart_without_live_operation_never_claims_approved_row` и `tests/test_approved_repository_integration.py::test_postgres_approved_graph_duplicate_decision_and_restart_have_no_authority` создают свежие координатор и runner при уже сохранённом approval. Без живого slot допуска нет. Это проверка потери in-memory authority через пересоздание объектов. Граф собирается с `checkpointer=False`. [Сборка StateGraph](../backend/app/agent_runtime/agent_graph.py#L185)

## Граница Step 10

Свежие PG-сессии уже подтверждают предварительный результат и `verifying`. Новый шаг может опираться на эту границу и на отдельное read-only наблюдение workspace. Доказательства агента и сведения об approval описывают ход исполнения. Успех требует независимой проверки фактического состояния и связи с критериями. При отсутствующем финальном audit verifier должен различать найденное изменение, частичный эффект и неизвестный исход.

Сохраняются documented debt для trusted fixture TOCTOU, кооперативной отмены, in-process composition, форматов ошибок и usage. Для BL-07 нужен неизменяемый снимок запроса перед редактированием Task. Для BL-09 отдельный SELECT текущего алгоритма требует READ COMMITTED. Sandbox, восстановление после restart и проверка live provider остаются своими этапами. В рассмотренных сценариях новых воспроизводимых блокеров security, terminal state, audit или approval не установлено.
