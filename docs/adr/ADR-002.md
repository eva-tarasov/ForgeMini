# ADR-002 — LangChain and LangGraph Agent Runtime

**Status:** принято владельцем проекта для направления Week 3; реализация и production-пригодность ещё не проверены.

## Context

Week 3 добавляет первый single-agent runtime в существующий modular monolith. [ADR-001](ADR-001.md) сохраняет архитектурные границы: `Task ≠ AgentRun`, backend владеет бизнес-состоянием, side effects требуют permission checks и необходимых approvals, а success — независимого verification evidence. Нынешние доменные переходы и `AgentRunService` сохраняют статусы и события, но ещё не исполняют агента; переход в `succeeded` сервис пока отклоняет.

## Decision

- Использовать LangChain для model abstractions, messages, tools и structured output. `create_agent` изучить как ограниченный учебный прототип, без второго production runtime.
- Основной production-minded runtime Week 3 строить на собственном LangGraph `StateGraph`. Будущий `LangGraphAgentRunner` должен реализовать независимый контракт Forge `AgentRunner`; доменные сервисы не должны зависеть от деталей графа.
- OpenAI рассматривать как первого model provider. Конкретная модель и версии зависимостей пока не утверждены. Минимальный прямой agent loop оставить учебной моделью; OpenAI Agents SDK отложить.
- Forge Domain и PostgreSQL остаются владельцами `Task`, `AgentRun`, `AgentEvent` и переходов состояний. LangGraph execution state не является источником истины для бизнес-состояния и требует явного mapping в доменные статусы и события.
- Завершение LangGraph execution само по себе не означает `AgentRun.succeeded`. Промежуточный успешный flow Week 3: `queued → running → verifying`. Только независимая verification с evidence может разрешить последующий переход в `succeeded`.
- Side effects выполнять после permission checks и, когда нужно, approvals. В Week 3 разрешён только безопасный fixture/read-only tool; полноценный Tool System относится к Week 4.
- Production checkpoints, durable recovery и выбор Temporal vs LangGraph оставить для Week 7. Week 3 не обещает resume после restart.

## Rationale

Владелец проекта выбрал LangChain и LangGraph, чтобы расширить образовательную цель Week 3: отдельно изучить готовые model abstractions и построение управляемого графа исполнения. Это осознанное учебное и архитектурное направление, а не вывод о доказанном техническом превосходстве над OpenAI Agents SDK. Пригодность интеграции для production должна быть подтверждена последующими тестами.

## Alternatives

- **OpenAI Agents SDK:** отложен. Его достаточность для требований Forge не опровергнута сравнительными тестами.
- **LangChain `create_agent` как основной runtime:** оставлен ограниченным учебным прототипом, чтобы не поддерживать два production пути исполнения.
- **Минимальный прямой loop:** полезен для понимания model/tool cycle, но остаётся учебным mental model.

## Trade-offs

- Два framework слоя повышают сложность изучения, интеграции, диагностики и обновления зависимостей.
- Возникает зависимость от API и экосистемы LangChain/LangGraph; независимый контракт `AgentRunner` ограничивает, но не устраняет vendor/ecosystem lock-in.
- Нужно явно сопоставлять execution state графа с доменным состоянием Forge, исключая ложный success и расхождения между событиями, статусом и результатом графа.
- Cancellation, timeout и ошибки во время исполнения потребуют отдельной проверки. Без production checkpoints нельзя обещать durable recovery или безопасный resume после остановки worker.

## Consequences

Week 3 должен проверить контракт runner, структурированный результат, сохранение доменных переходов и событий, bounded execution, обработку ошибок и usage/cost. Независимая verification остаётся обязательной для success. Это требования к будущей реализации, а не утверждение, что граф, инструменты или эти проверки уже существуют.

## Future Review Triggers

- Тесты выявят, что mapping состояний, cancellation, ограничения исполнения или интеграция с доменными сервисами не соответствуют exit criteria Week 3.
- Изменятся требования к model provider, зависимостям, стоимости, наблюдаемости или безопасности side effects.
- В Week 7 появится потребность в checkpoints, approval pause/resume и recovery после worker restart: сравнить Temporal и LangGraph на одном сценарии до выбора durable orchestration.
